Коммерческое предложение документ планирования. Данный документ не генерирует проводки и потому может быть скорректирован после добавления в систему. Редактирование Предложения возможно до момента создания на его базе Заказа на продажу. Так как Заказ на продажу создаётся построчно, то Система позволяет вносить изменения в строках, которые ещё не были скопированы в Заказ на продажу.

## Создание документа
Для создания Предложения необходимо выполнить следующие шаги:
1. Открыть форму документа Предложение, для этого из Главного меню прости по пути Продажи -> Предложение

<img src="/.attachments/image-d664d2c8-05ef-49be-a102-bab543d7a9e6.png" alt="image.png" width="100%" />


2. В открывшемся документе заполнить Заголовок
(1) Указать Клиента  
(2) Опционально ввести ссылочный номер документа. Это или номер в системе Клиента, или внутренний SAP реферес которая будет доступна в последующих документах. Например это может быть "Меню клиента А на август 2026"  
(3) Указать дату регистрации (дата создания Предложения) и дату Действительно по (максимальная дата по которую из данного Предложения можно будет генерировать заказы.  

<img src="/.attachments/image-c57769a4-8325-474f-a702-6a7c9100e733.png" alt="image.png" width="100%" />

3. Перейти к заполнению матрицы документа на вкладке Содержание.
* В данном примере будет рассмотрен вариант визуального разделения записей в таблице. Функционал описанный в п.4 используется только как разделитель. Он не является требованием. Товары могут быть добавлены в виде сплошной таблицы (см.описание с п.5)
4. В первой строке в колонке Тип выбрать в выпадающем меню выбрать пункт Текст 

<img src="/.attachments/image-3aa95a7a-1d76-49c9-8728-8b9656cd5ae5.png" alt="image.png" width="100%" />

4.1. Система откроет текстовое поле для ввода свободного текста  
4.2. Ввести необходимый текст и нажать кнопку [ОК] для его сохранения

<img src="/.attachments/image-b8304b86-fd89-4a61-85d7-abb5b35e23d8.png" alt="image.png" width="100%" />

5. Заполнить матрицу документа следующим образом:

<img src="/.attachments/image-0c548733-d63c-4672-b24e-0b1aa919e4d7.png" alt="image.png" width="100%" />

(1) Указать товар. Заполнение может быть произведено в любом из полей Код или Имя товара. При этом автоматически будут заполнены поля Название на руссом и Название на локальном языке. (Источник этих данных - карточка товара)  
(2) Указать количество планируемое к реализации.  
(3) Проверить соответствие единиц измерения (Источник этих данных - карточка товара)  
(4) Указать цену реализации. Цена указывается до налога. По-молчанию цена указывается в валюте Клиента.  
(5) Проверить и скорректировать код VAT налога. (Источник этих данных - карточка клиента)  
(6) Указать склад отгрузки. Этот склад будет использован для расчёта Потребности в товарах.  
(7) Указать согласованную дату отгруки товара в строке. Если Предложение создаётся с различными данными по одному товару то необходимо создать несколько строк с указанием для каждой строки - своей даты отгрузки.  
(8) Указать Key/Department центры.  
(9) Проверить и указать корректный Договор, связанный с данной поставкой. При наличии в Системе только одного действующего Договора - поле будет заполнено автоматически. 
6. Аналогичным образом заполнить остальные строки

<img src="/.attachments/image-e5521171-229f-40cc-b01c-8fa3555e3eec.png" alt="image.png" width="100%" />

7. Перейти на вкладку Логистика и проверить \ Указать адрес доствки по данной отгрузке. **Данная  информация относится к документу в целом, но при необходимости в Документе есть возможность настройки для распределения по разным адресам построчно**

<img src="/.attachments/image-f6afe103-9b92-4952-a45d-07e4a8455f3f.png" alt="image.png" width="100%" />

8. Выбрать свою подпись в поле Ответственный

<img src="/.attachments/image-923b85e5-7621-4854-af19-9f1077fb5b3d.png" alt="image.png" width="100%" />

9. Нажать кнопку [Добавить] для сохранения Предложения в системе.

## Запуск расчёта Потребности \ Demand 
1. Открыть ранее сохранённое Предложение (расчёт Потербности возможен только для документа добавленного в базу данных)
2. Нажать комбинацию клавиш запуска Динамического отчёта [F2] -> [F12]
Данная настройка является пользовательской и зависит от того как каждый из пользователей организовал свою работу в системе.
3. Система выполнит расчёт Потребности и отобразит результат в табличном виде. Для работы с таблицей доступны инструменты фильтрации и сортировки, расположенные на Панели инструментов

<img src="/.attachments/image-bf4c9994-054f-4fde-a56f-2e4773b452ee.png" alt="image.png" width="100%" />

4. Таблица расчёта Потребности формируется следующим образом:
(описание действительно для версии 1.0 процедуры расчёта Потребности, актуальной на момент составления инструкции)  
В отчёте отображаются **только позиции с потребностью**.  
Например: Если для производства яичницы необходимо 10 яиц, которые имеются на складе то яйцо не будет показано в отчёте как потребность. Но, если в момент расчёта в системе уже будет находиться заказ на другое блюдо требующем яйцо, то яйцо будет отражено в Потребности.  
Правило сверки:  
Количество на складе - Количество в продажах + Количество в закупках - Количество потребности  
Расчёт выполняется от верхней спецификации к низшей и затем до ингредиентов. 

<img src="/.attachments/image-344a51ef-892c-47f2-85eb-0b2f939825b6.png" alt="image.png" width="100%" />

(1) Тип Потребности. Закупка - товары необходимо закупить (не являются спецификациями) для этих товаров необходимо сформировать Зявку на закупку. Производство - позиции со Спецификациями, для этих товаров необходимо сформировать Производственный заказ  
(2) Очерёдность создания обработки строк. Техническая особенность SAP - пустое поле означает 0 (это значение не отображается)  
(3) Глубина - информационная колонка, отображает степень вложенности спецификаций  
(4) Код и наименование товара  
(5) Код склада. Наличие товаров, наличие заказов определяется только в рамках указанного склада  
(6) Требуемое количество. Количество потребности собранное отчётом со всех уровней спецификаций.  
(7) Количество для заказа. Количество которое сформировано из потребности с учётом кратности заказа. Источник кратности заказа - Спецификация для производственных позиций и карточка товара для закупаемых.  
Например, десерт можно произвести только в количестве 16 кусков. Следовательно при продаже 35 штук, система скалькулирует требуемое количество как 48  
(8) Кратность заказа - информационная колонка отображающая коэффициент кратности использованный при расчёте  
(9) На складе - количество товара на складе, указанном в колонке (5)  
(10) Заказано (продажа). Количество товара для которого в системе созданы Заказы на продажу, Производственные заказы, Запросы на перемещение (исходящие). Для склада,указанного в колонке (5)  
(11) Заказано (закупка). Количество товара для которого в системе созданы Заказы на закупку, Производственные заказы, Запросы на перемещение (входящие). Для склада,указанного в колонке (5)  
(12) Используется в товарах. Информационная колонка отображающая, в каких спецификациях **данного расчёта** используется товар из строки

## Экспорт расчёта Потребности \ Demand 
Для упрощения переноса данных в Заявку на закупку и Производственные заказы необходимо экспортировать расчёт Потребности в Excel. Для этого 
1. Нажать на кнопку Excel расположенную на Панели инструментов

<img src="/.attachments/image-f0b688be-6ade-421e-82c5-527400a4fa6b.png" alt="image.png" width="100%" />

2. В открывшемся окне укзаать путь для сохранения файла и выбрать формат *.xlsx и нажать кнопку [Save]

<img src="/.attachments/image-bc5b611c-11e8-47d6-a407-ac4df0865216.png" alt="image.png" width="100%" />

3. Система откроет окно выбора подхода к формату числовых полей
Необходимо выбрать ответ Нет. Данный выбор обеспечит совсестимость числового формата полей в Excel

<img src="/.attachments/image-914a11f4-04be-4d62-adaa-16ec9672a459.png" alt="image.png" width="100%" />

4. Файл расчёта Потребности сохранён и может быть использован для создания документов снабжения.
